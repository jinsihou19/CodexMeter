它本质上是一个“本地会话日志 → Token 聚合 → 按模型定价 → Swift Charts 展示”的成本估算功能，不是直接读取 OpenAI 账单。

主要链路：

1. 从 `$CODEX_HOME/sessions` 或 `~/.codex/sessions`，以及 `archived_sessions` 读取 Codex 的 JSONL 会话记录，解析模型、日期、工作目录、输入/缓存/输出 Token。[CostUsageScanner.swift](/Users/jinsihou/Projects/stars/CodexBar/Sources/CodexBarCore/Vendored/CostUsage/CostUsageScanner.swift:814)

2. 按定价计算估算成本：

   `非缓存输入 × 输入单价 + 缓存输入 × 缓存单价 + 输出 × 输出单价`

   单价优先使用 models.dev 的缓存数据，缺失时回退到内置价格表；长上下文和 Priority/Fast 模式有独立处理。[CostUsagePricing.swift](/Users/jinsihou/Projects/stars/CodexBar/Sources/CodexBarCore/Vendored/CostUsage/CostUsagePricing.swift:521)

3. 聚合成每天、每模型、每项目的统计。项目路径来自会话元数据里的 `cwd`；Git worktree 会尽量归并到主项目，最后按成本从高到低排序。[CostUsageScanner+Projects.swift](/Users/jinsihou/Projects/stars/CodexBar/Sources/CodexBarCore/Vendored/CostUsage/CostUsageScanner+Projects.swift:3)

4. `CostUsageFetcher` 扫描并缓存结果，默认取最近 30 天，同时生成：

   - 每日成本与 Token
   - 每日模型明细
   - 30 天估算总计
   - 项目成本排名

   [CostUsageFetcher.swift](/Users/jinsihou/Projects/stars/CodexBar/Sources/CodexBarCore/CostUsageFetcher.swift:143)

5. UI 使用 SwiftUI `Chart` 的 `BarMark` 绘制每日柱状图。最高柱顶端额外叠一小段黄色标记；鼠标悬停通过 `chartOverlay` 选中日期，并显示当天的模型、金额和 Token。[CostHistoryChartMenuView.swift](/Users/jinsihou/Projects/stars/CodexBar/Sources/CodexBar/CostHistoryChartMenuView.swift:63)

底部 Projects 最多展示成本最高的 5 个项目；同一主项目如果包含多个 worktree/source，还会继续展示子路径。[CostHistoryChartMenuView.swift](/Users/jinsihou/Projects/stars/CodexBar/Sources/CodexBar/CostHistoryChartMenuView.swift:246)
